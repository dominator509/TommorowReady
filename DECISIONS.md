# Decisions

| ID                                                                                          | Decision                                                                                                                   | Rationale                                                                                                                                                       | Status                                                                   |
| ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| ADR-001                                                                                     | Modular monolith                                                                                                           | Lowest operating complexity with clear extraction boundaries                                                                                                    | Accepted                                                                 |
| ADR-002                                                                                     | PostgreSQL is authoritative                                                                                                | Transactions, RLS, and durable evidence                                                                                                                         | Accepted                                                                 |
| ADR-003                                                                                     | AI is optional and non-authoritative                                                                                       | Privacy and accuracy                                                                                                                                            | Accepted                                                                 |
| ADR-004                                                                                     | Consequential actions require payload-bound authorization                                                                  | Liability and duplicate prevention                                                                                                                              | Accepted                                                                 |
| ADR-005                                                                                     | Native auth with passkeys and TOTP                                                                                         | Avoid required social providers                                                                                                                                 | Accepted                                                                 |
| ADR-006                                                                                     | No credential vault or autonomous payment                                                                                  | Reduce catastrophic risk                                                                                                                                        | Accepted                                                                 |
| ADR-007                                                                                     | Manual production deploy                                                                                                   | No authorization supplied                                                                                                                                       | Accepted                                                                 |
| ADR-008                                                                                     | Use pinned real local PostgreSQL, Valkey, MinIO, and Mailpit services for engineering                                      | The operator authorized real local provisioning; these services preserve protocol behavior without claiming cloud-provider verification                         | Accepted                                                                 |
| ADR-009                                                                                     | Preserve EP-000 as unverified while later implementation is continued if its full-suite gate remains structurally circular | EP-000 demands `verify.sh`, while `verify.sh` requires artifacts assigned to EP-001 and EP-007; no sentinel will be fabricated                                  | Accepted for implementation continuation only; final ship gate unchanged |
| ADR-010                                                                                     | Separate PostgreSQL migration owner from the forced-RLS application role                                                   | Real integration testing proved the Docker bootstrap superuser bypasses RLS and cannot be demoted; a distinct non-superuser role makes tenant isolation genuine | Accepted                                                                 |
| ADR-011                                                                                     | Rehearse immutable non-root containers locally but defer the production platform overlay                                   | No production cluster, registry, ingress, DNS, secret manager, or approved network endpoints are available; local process and dependency readiness can still be proven without inventing provider values | Accepted; production deployment remains blocked                          |
| ADR-012                                                                                     | Pin GitHub Actions by commit SHA and container inputs by exact version plus registry digest                                 | Hosted verification exposed a deprecated action runtime, while tags alone remain mutable; immutable references make CI and local infrastructure reproducible and auditable                         | Accepted                                                                 |
| ADR-013                                                                                     | Derive tenant, household, actor, role, grants, purpose, and assurance only from a validated signed session at the API boundary | The security scan proved caller-selected context headers bypassed both authentication and RLS intent; signed claims plus per-route deny-by-default authorization establish one enforceable trust boundary | Accepted                                                                 |
| ADR-014                                                                                     | Encrypt canonical payloads with context-bound AEAD and use a distinct authenticated-encryption key for backups              | RLS does not protect database snapshots or backups; binding ciphertext to tenant, household, table, and record prevents substitution while separate keys limit cross-purpose compromise               | Accepted; production key wrapping and rotation remain KMS-gated          |
| ADR-015                                                                                     | Issue only bounded first-party sessions and provision local owners through an ignored credential artifact                    | The API previously verified signed claims but had no real issuer path; encrypted identity lookup, Redis throttling, issuer/audience/JTI claims, TOTP assurance, and non-printing local bootstrap create a testable trust boundary without embedding credentials          | Accepted; passkeys, recovery, and production secret custody remain open  |
| New decisions require context, options, choice, consequences, evidence, and affected specs. |
